# UX 시나리오와 자가 검증

앱을 실제로 띄워 화면을 캡처하고, 아래 시나리오를 따라가며 걸리는 곳을 적었다.
검증 기준은 "처음 쓰는 사람이 멈추지 않고 목적을 끝내는가"와 "화면이 정보를 위계 있게 보여주는가"다.

측정 환경: Windows 10 Home, 1600×900 창, 세션 249건 / 1.28 GB, 테마 시스템(라이트).

## 고친 것

### 공통 (ARCHITECTURE §6.2로 규칙화)

- 본문은 왼쪽 정렬 + 최대 폭 1280. 넓은 창에서 가운데로 떠 좌우가 비던 문제를 없앴다
  (`HorizontalAlignment=Left` + `MaxWidth`는 폭이 내용에 맞춰 줄어들므로, 열에 `MaxWidth`를 주고 내용은 Stretch로 채운다)
- 페이지마다 `제목 → 부제 → 행동 → 카드` 순서로 통일. 카드·글자 스타일을 6개로 제한
- 목록의 한 줄은 한 줄로 끝낸다 (`TextWrapping=NoWrap` + 말줄임). 전체 값은 ToolTip
- 큰 수는 `Formats.Tokens`로 줄여 쓰고(729,015,129 → 729.0M) 정확한 값은 ToolTip
- 파괴적인 버튼은 대상이 없으면 비활성. 빈 상태는 흰 판 대신 다음에 할 일을 적는다
- 왼쪽 이동 메뉴도 한국어로 (요약·터미널·세션·규칙·설정)

## 3차: 테마

`다크`를 골라도 화면이 바뀌지 않는다는 보고를 받고 원인을 두 개 찾았다.

1. 테마를 창 생성 시점에만 적용해서, 고르고 저장해도 다시 시작할 때까지 그대로였다
   → 고른 즉시 적용하고 즉시 저장한다
2. `MicaBackdrop`은 OS 테마를 따라가므로, 시스템이 라이트인데 앱만 다크로 두면 배경은 밝고 글자만 밝아진다
   → 명시적 테마에서는 Mica를 끄고 그 테마의 단색으로 칠한다
3. Windows 10은 제목줄 색 API(`AppWindowTitleBar` 색상)를 지원하지 않아 위쪽에 밝은 띠가 남았다
   → `ExtendsContentIntoTitleBar`로 제목줄을 앱이 직접 그린다 (아이콘 + 앱 이름, 드래그 영역 유지)

확인: 시스템 · 라이트 · 다크 세 값을 차례로 골라 캡처했다. 세 경우 모두 창 전체(제목줄 포함)가 같은 테마로 보이고,
다시 시작 없이 즉시 바뀐다. 설정 파일의 값도 고른 즉시 반영된다.

## 4차: 폴더는 이미 아는 것에서 고른다

"폴더 선택 대화상자가 뜨긴 하는데, 세션 탭 때문에 어차피 무슨 프로젝트가 있는지 알지 않나"는 지적을 받았다. 맞다.
인덱스에 프로젝트 경로가 이미 있는데 OS 대화상자로 파일 시스템을 헤매게 할 이유가 없다.

- `KnownProjects`(App/Services): 최근 폴더 + 세션 인덱스의 프로젝트를 최근 순으로 합치고, 사라진 폴더는 뺀다 (최대 20개)
- RuleMaker의 `프로젝트 폴더`와 Terminal의 `작업 폴더`에서 **아는 프로젝트 ▾** 하나로 고른다.
  목록에 없는 폴더만 맨 아래 `다른 폴더 고르기…`로 대화상자를 연다
- 목록 이름은 폴더 이름만. 겹치면 **처음으로 달라지는 상위 폴더**만 하나 붙인다
  (`as-r / TASK-1`, `as-m1 / TASK-1`, `GitHub / JBroEngine`, `repos / JBroEngine`).
  중간 단계를 다 붙이거나 전체 경로를 노출하지 않는다. 규칙은 `Formats.Labels` 하나로 두고 Sessions 트리도 같은 것을 쓴다

확인: 드롭다운 항목을 뽑아 20개가 모두 서로 다른 이름으로 나오는 것을 봤다.
전체 경로는 각 항목 ToolTip에 있다.

## 5차: 연동 확인에서 찾은 것

"연동 눌러보고 CLAUDE.md 잘 들어갔는지 확인해봐"를 실제로 해봤다. 임시 폴더 두 곳에서 확인했다.

- 규칙이 채워진 상태: `PROJECT_RULES.daiso` 저장 + `CLAUDE.md`에 마커 블록 추가 + `AGENTS.md` 생성.
  기존 `CLAUDE.md`의 세 줄은 **CRLF까지 그대로**, BOM 없음
- 규칙이 비어 있는 상태: 연동이 눌리는데 파일은 하나도 안 쓰이고
  `규칙을 저장할 수 없습니다 / line 4, column 13 / 'action' 값이 비어 있다` 대화상자만 떴다.
  사용자는 YAML을 쓴 적이 없으니 줄·열은 도움이 안 된다

고친 것:
- 저장·다른 이름으로 저장·연동은 **저장할 수 있을 때만 활성** (`CanSave`: 이름 + 행동 1개 이상)
- 비워 둔 입력 줄은 저장에서 버린다. 조건이나 행동이 빈 규칙은 저장 대상에서 빠진다
- 저장 실패 메시지는 사람 말로. 줄·열은 파일을 열다 실패했을 때만 보여준다

재확인: 빈 상태에서 연동 버튼이 `DISABLED`, 이름과 행동을 채우면 눌려서 세 파일이 정확히 기록됐다.

## 6차: NOT은 UI에서 뺀다

"룰메이커에 NOT은 필요없지 않나? 그냥 말로 풀어쓰면 되는데" — 맞는 말이다.
조건 리프가 자유 문장이라 `테스트 코드가 아닐 때`로 쓰면 되고, 그러면 트리 편집 메뉴도 짧아진다.

- `추가 ▾`와 `감싸기 ▾`에서 NOT 항목을 뺐다 (남은 것: 리프 · AND · OR)
- **파일 형식·파서·렌더러는 그대로 둔다.** `not`이 든 기존 `.daiso`는 계속 열리고 트리에 NOT 노드로 보이며, 마크다운은 `!조건`으로 렌더된다
- 근거는 REQUIREMENTS §6.3에 한 줄로 남겼다

## 7차: 유료 배포 기준으로 다시 몰아본 감사

앱을 직접 띄워 창 크기·흐름·상태를 하나씩 확인했다. 이번에 잡은 것은 대부분 **처음 쓰는 사람이 바로 만나는 문제**였다.

### 막히던 것

| 위치 | 문제 | 조치 |
|---|---|---|
| Sessions | 1024×700에서 가운데 목록이 **40px로 짜부라져** 제목이 안 보였다 (290+400 고정 열) | 3열 → 2열. 프로젝트 선택을 필터 바 드롭다운으로 올리고, 목록은 `*`+`MinWidth 320`, 상세만 400 고정 |
| Sessions | 배경 인덱싱과 화면이 같은 SQLite 연결을 써서 `인덱스 갱신 실패: Index was out of range` | 읽기는 호출마다 새 연결, 쓰기는 전용 연결 + 세마포어 (WAL이라 읽기가 안 막힌다) |
| 전체 | 800×600으로 줄이면 상세 열이 화면 밖으로 잘렸다 | 창 최소 크기를 1024×700으로 강제 (`OverlappedPresenter`) |
| Sessions 상세 | 세션을 골라도 몇 초간 **빈 판**이었다 (큰 세션 파싱) | "대화를 읽는 중입니다…" + 진행 표시, 다 읽고 비면 안내 |
| Sessions 상세 | `Tool · 22:01:18` 접힌 줄이 대화를 밀어냈다 | 기본은 대화만. 도구 호출·시스템은 `도구 호출 보기` 토글 |
| Sessions | 인덱싱이 끝나도 목록이 옛 숫자를 유지했다 | 인덱싱 완료 시 목록·요약 자동 갱신 |

### 어긋나던 것

| 위치 | 문제 | 조치 |
|---|---|---|
| 왼쪽 메뉴 | `요약` 안에 또 `요약 / 사용량` 탭이 있었다 | 사용량을 상위 메뉴로 올리고 중첩 탭 제거 (메뉴 6개) |
| 페이지 제목 | 메뉴는 `요약`인데 제목은 `도구 상태` | 제목은 메뉴와 같은 말로, `도구 상태`는 섹션 제목으로 내림 |
| 검색 | 지운 뒤에도 `'PROJECT_RULES' 결과 18건`이 남았다 | 지우면 목록 기준 문구로 되돌림 |
| 검색 | 결과를 보는 중에도 목록 옆 숫자가 프로젝트의 세션 수였다 | 검색 중에는 `결과 N건`, 프로젝트 필터는 잠금(검색은 전체 대상) |
| 타임라인 | 역할이 `User` / `Assistant` 영어였다 | 사용자·어시스턴트·도구·시스템으로. 시각은 분까지, 사람 말에는 왼쪽 강조 바 |
| 사용량 | `JBroEngine`이 두 줄로 겹쳐 보였다 | 세션 화면과 같은 `Formats.Labels` 규칙 적용 |
| 필터 바 | 1024에서 `아카이브 포함`이 잘렸다 | 최소 크기·고아만·아카이브를 `필터` 팝오버로 묶고 초기화 버튼 추가 |
| 아이콘 | 폴더 글리프가 네모로 렌더됐다 | `SymbolIcon Symbol="Folder"`로 교체 |

### 새로 넣은 것

- 첫 실행(인덱스 없음)에 빈 목록 대신 인덱싱 진행을 보여준다. 임시 인덱스 경로로 실제 재현해 확인했다
- `Ctrl+1`~`Ctrl+6` 페이지 이동, `Esc` 검색 지우기. 설정에 **단축키** 카드로 적어 발견되게 했다
- `daiso refresh` — 앱 없이 인덱스를 갱신하는 CLI 명령

### 확인 방법

같은 시나리오를 자동화로 다시 몰았다: 검색(18건) → 결과 트리 → 지우기, 요약의 `이어서 열기` → 터미널에 `claude --resume <id>` 채워짐,
세션 선택 → 로딩 → 대화 표시, `골라 체크 → 큰 것 선택` → 선택 1건 · 휴지통 버튼 활성, `Ctrl+1`~`6` 이동, 700×500으로 줄여도 1024×700 유지,
인덱싱 완료 후 부제가 `프로젝트 34개 · 세션 249건`으로 자동 갱신.

남은 것: `다른 폴더 고르기…`로 여는 대화상자의 확정 클릭(흔한 경로가 아니다), 실제 터미널 실행·Markdown 내보내기(창·대화상자를 띄우므로 CLI로만 검증).


## 8차 — 로그인 프로필 UI 검수

가짜 홈(`fakehome`)과 가짜 보관 폴더(`DAISO_PROFILES_DIR`)를 만들어, 실제 로그인 파일은 건드리지 않고 앱 UI만으로 전 과정을 몰았다.

| 단계 | 확인한 것 |
|---|---|
| 저장 | `지금 로그인 저장` → 도구·이름 입력 → `‘계정 A’(으)로 저장했습니다` |
| 목록 | 계정 라벨·이메일·저장 시각이 한 줄로. 토큰은 어디에도 없다 |
| 전환 | 홈을 계정 B로 바꾼 뒤 `이 계정으로` → 파일 바이트가 A로 복원, 위 도구 상태 카드도 자동 갱신 |
| 되돌리기 | `직전 상태`를 눌러 다시 B로. 두 번 누르면 서로 맞바뀐다 |
| 삭제 | `직전 상태 프로필을 지울까요? / 저장해 둔 로그인 정보가 사라집니다. 지금 로그인한 계정은 그대로입니다` → 폴더까지 사라짐 |
| 레이아웃 | 1400·1024 모두 카드가 깨지지 않는다 |

### 고친 것

| 곳 | 문제 | 고침 |
|---|---|---|
| 직전 상태 | `로그인 정보 없음`만 떠서 **어디로 되돌아가는지 알 수 없었다** | 되돌리기 직전 `AuthStatus`를 함께 넘겨 계정 라벨·이메일을 meta에 남긴다 |
| 상태 문구 | `계정 A 계정으로 바꿨습니다` — 이름에 '계정'이 들어가면 말이 겹친다 | 이름을 따옴표로 감싼다: `‘계정 A’(으)로 바꿨습니다` |

`만료 정보 없음`은 결함이 아니었다. 판정은 `refreshTokenExpiresAt`으로 하는데 시험용 파일에 그 값이 없었을 뿐이고, 실제 파일에서는 `2026-10-03까지 · 24일 남음`으로 나온다.

### 정리

검수가 끝난 뒤 설정의 세션 루트 재정의를 UI로 비우고, 가짜 폴더 두 개를 지웠다. 실제 `%LOCALAPPDATA%\d-AI-so\profiles`는 만들어지지 않았다.


## 9차 — 여섯 화면 전체 감사 (유료 기준)

여섯 화면을 순서대로 띄워 1400×900과 1024×700에서 각각 찍어 놓고 비교했다.

### 일관성 — 스스로 정한 규칙을 어긴 곳

| 곳 | 문제 | 고침 |
|---|---|---|
| 터미널 · 규칙 | 왼쪽 메뉴 이름과 페이지 제목이 달랐다 (`터미널` / `터미널 열기`) | 제목을 메뉴 이름과 같게 (ARCHITECTURE §6.2) |
| 사용량 | 같은 `다시 읽기`가 요약에서는 글자, 사용량에서는 아이콘만이었다 | 아이콘+글자로 통일 |
| 터미널 | 본문 최대 폭만 900이라 다른 화면보다 좁았다 | `ContentMaxWidth`로 통일 |
| 규칙 | 이 화면만 부제가 없었다 | 무엇을 하는 화면인지 한 줄 추가 |
| 터미널 · 설정 | 같은 화면에서 경로가 원화 기호와 역슬래시 두 가지로 보였다. 한국어 본문 글꼴이 역슬래시를 원화 기호로 그린다 | 경로를 보여주는 곳은 모두 고정폭 글꼴로. 입력칸 머리글은 본문 글꼴 유지 |

### 레이아웃

| 곳 | 문제 | 고침 |
|---|---|---|
| 규칙 (1024) | **행동 문장 입력칸이 한 글자 폭으로 짜부라졌다** | 편집·미리보기 두 열에 최소 폭을 주고, 미리보기를 고정 420에서 비율로 바꿔 좁은 창에서 넘치지 않게 |
| 규칙 | 조건 트리 아래 정체를 알 수 없는 빈 회색 상자가 있었다 | `조건식` 라벨을 붙이고, 비었을 때 무엇을 하면 되는지 적는다 |
| 사용량 | 막대와 숫자 사이가 300px 넘게 떠 눈이 두 번 움직였다 | 숫자를 막대 옆으로 |
| 설정 | 두 경로 입력칸의 오른쪽 끝이 어긋나 있었다 | 아래 칸에도 같은 크기의 자리를 둬 끝을 맞춘다 |
| 요약 | 프로필이 없을 때 빈 목록이 자리를 차지해 카드가 떴다 | 비어 있으면 목록을 감춘다 |

### 문구

- 요약 화면 부제가 보안 공지(`토큰 값은 … 쓰지 않습니다`)였다. 화면을 설명하는 자리라 부제는 화면 설명으로 바꾸고, 그 약속은 **설정 > 정보** 카드로 옮겼다

### 새로 넣은 것 — 설정 > 정보

유료로 파는 프로그램이 앱 안에서 밝혀야 하는 것을 한 카드에 모았다. 판 번호(`d-AI-so 1.0.0`), 인터넷에 아무것도 보내지 않는다는 것,
로그인 정보를 이 PC 사용자 계정으로만 풀 수 있게 암호화해 둔다는 것, 이 앱이 쓰는 경로 세 곳, 상표 고지.


## 10차 — 요약 화면 재배치

대분류를 짚다가 요약 화면 자체가 틀렸다는 걸 봤다. 세 가지였다.

| 문제 | 고침 |
|---|---|
| **가장 자주 쓰는 `최근 세션`이 제일 아래**라 1400×900에서 제목만 걸치고 잘렸다. 1024×700에서는 아예 안 보였다 | 도구 상태 바로 아래로 올렸다. 이제 두 크기 모두에서 목록이 보인다 |
| **로그인 프로필이 화면 한복판**을 차지했다. 계정을 오갈 때만 쓰는, 빈도가 가장 낮은 기능인데 지분은 최근 세션보다 컸다 | 카드를 없애고 **각 도구 카드의 `계정` 팝오버**로 옮겼다. 버튼에 `계정 1`처럼 개수가 붙고, 저장할 때 도구를 고르는 단계가 사라졌다 |
| 세션 카드에 세션 수·용량(세션 소관)과 최근 7일 토큰(사용량 소관)이 섞여 있는데 **문은 `세션 보기` 하나뿐**이었다 | `사용량 보기`를 나란히 뒀다 |

`컨텍스트`는 세션 화면에 그대로 두기로 했다.

팝오버는 기본 `FlyoutPresenter`가 456px에서 잘라 `이 계정으로` 버튼이 반쯤 사라졌다. 최대 폭을 620으로 풀고 내용 폭을 540으로 고정해
이름·계정·시각·버튼 둘이 한 줄에 들어오는 것을 저장 → 목록 → 삭제 순서로 앱에서 확인했다.

## 11차 — 기본 프리셋과 갤러리

빈 규칙 화면은 처음 온 사람에게 막막하다. 기본 제공 프리셋 14개(Git, 테스트, 리뷰, 리팩터링, 보안, 문서, API, C#, C++, Python, TypeScript, Rust, Unity, 한국어 소통)를 앱에 묻고,
규칙 화면 명령바의 `프리셋` 버튼에서 갤러리로 연다.

| 확인한 것 | 결과 |
|---|---|
| 갤러리 열기 | 왼쪽 목록 14개(갈래 · 출처 / 이름 / 한 줄 설명), 오른쪽에 고른 것의 Markdown 미리보기와 `항상 적용 3 · 조건 규칙 4` |
| `새로 열기` | 편집기에 그대로 채워지고 `‘Git 커밋 규칙’ 프리셋을 열었습니다. 저장하면 내 파일이 됩니다`. 경로가 없어 저장 버튼은 다른 이름으로 저장처럼 동작한다 |
| `지금 규칙에 추가` | 이미 Git이 열린 상태에서 Git을 다시 합치자 전역 행동 3개는 걸러지고 조건 규칙 4개가 붙었다 → **규칙도 같은 조건·같은 행동이면 건너뛰게 고쳤다** |
| 1024×700 | 갤러리 팝오버(820px)가 창 안에 들어온다 |

### 고친 것

| 문제 | 고침 |
|---|---|
| 목록 항목의 접근성 이름이 클래스 이름이었다 | `ToString()`이 프리셋 이름을 돌려준다 |
| 같은 프리셋을 두 번 합치면 규칙이 두 배가 됐다 | 조건식과 행동 문장이 모두 같은 규칙은 건너뛴다 |
| 미리보기 빈 안내가 행동 입력만 말했다 | `위의 프리셋에서 시작하면`을 덧붙였다 |

넘침 메뉴의 `프리셋 라이브러리` 목록은 갤러리에 흡수했고 `라이브러리에 저장`만 남겼다. 저장한 파일은 갤러리를 다시 열면 `내 라이브러리` 갈래로 바로 보인다.

## 12차 — 전체 화면 최종 점검과 판단

여섯 화면을 1400×900과 1024×700에서 순서대로 걸으며 캡처해 대조했다.

| 본 것 | 결과 |
|---|---|
| 제목·부제·우측 동작의 자리 | 여섯 화면 모두 같은 자리. 요약·사용량은 `다시 읽기`, 세션은 검색, 규칙은 명령바, 설정은 하단 저장 |
| 카드 문법 | 같은 모서리·여백·제목 크기. 빈 상태는 모두 `NoticeBorder` 한 줄 안내 |
| 1024×700 | 잘리는 화면 없음. 세션 목록 제목은 말줄임, 규칙 편집기는 두 열 유지, 팝오버(계정·프리셋)는 창 안 |
| 문구 | 존댓말 통일. 쓰지 않는 문구 키 17개 정리(동적 조합 없음을 확인한 뒤) |

### 판단

**UI/UX는 유료로 배포할 수 있는 수준이다.** 처음 켠 사람이 요약에서 로그인 상태와 최근 작업을 보고, 이어서 열고, 규칙은 프리셋에서 시작하고,
계정은 도구 카드 안에서 바꾸는 흐름이 막히는 곳 없이 이어진다. 화면마다 문법이 같아 한 화면을 배우면 나머지를 안다.

배포 전에 남은 것은 화면이 아니라 포장이다: 실행 파일 코드 서명, 업데이트 경로. 이 둘은 앱 안에서 고칠 것이 아니라 배포 파이프라인의 일이다.

## 13차 — 내 프롬프트 대분류

규칙과 다른 종류의 물건(한 번 실행하는 절차)을 규칙 화면에 끼우지 않고 대분류로 뗐다. `규칙`은 `내 규칙`으로 이름을 맞췄다.

프롬프트 원문(소규모 프로젝트 탑다운 기획 인터뷰)은 넣기 전에 반례를 찾아 고쳤다: 시작 질문이 두 군데에서 달랐던 것, 프로젝트 종류(라이브러리·모드·스크립트)를 묻지 않아 플랫폼 선택지가 어긋나던 것,
기존 코드가 있는 경우, Q4·Q6 중복, 어휘 두 벌, PROPOSED가 확정되는 단계 없음, 부분 응답·회차 상한 규칙 없음, 문서 19절, 그리고 **코딩 에이전트가 절차 도중 파일을 만들기 시작하는 것**을 막는 첫 문장.
H1 하나·예시는 인용 블록으로 정리하고 결과 파일을 `docs/PROJECT_PLAN.md`로 정했다.

| 확인한 것 | 결과 |
|---|---|
| 메뉴 | `내 규칙`, `내 프롬프트` 7개. `Ctrl+1~7` |
| 목록 | 기본 제공 2개(기획 · 파악). 배지 `기획 · 기본 제공` |
| 고쳐 저장 | 이름을 바꿔 `내 프롬프트에 저장` → `내 것` 배지로 세 번째 줄 |
| 프로젝트에 넣기 | `docs/prompts/{id}.md`에 **본문만** 생김. 시작 메시지 `docs/prompts/… 파일을 읽고 그 절차대로 진행해 주세요. 결과는 docs/PROJECT_PLAN.md 에 씁니다.`가 복사 버튼과 함께 뜸 |
| 삭제 | 확인 대화상자 → 보관함 폴더까지 비움 |
| 1024×700 | 두 열 유지 |

### 고친 것

| 문제 | 고침 |
|---|---|
| 기본 제공을 그대로 넣어도 파일 이름이 이름에서 만든 한글 슬러그가 됐다 | 고른 항목의 id를 그대로 쓴다. 새로 만든 것만 이름에서 id를 만든다 |

터미널 화면의 프롬프트 드롭다운(적용 여부 표시)은 다음으로 미뤘다.

## 14차 — 내 규칙을 내 프롬프트와 같은 골격으로

내 규칙의 프리셋 목록이 팝오버 안에 숨어 있어 두 화면의 문법이 달랐다. 내 규칙도 **좌 목록 · 구분선 · 우 편집기**로 바꾸고, 두 화면 모두 구분선을 끌 수 있게 했다.

| 확인한 것 | 결과 |
|---|---|
| 내 규칙 좌측 목록 | 기본 제공 14 + 내 라이브러리. 배지 · 이름 · 설명. 아래 `새로 열기` / `지금 규칙에 추가` |
| 구분선 끌기 | 마우스로 끌면 목록 폭이 바뀌고, 놓으면 설정에 저장. 다음 실행에 그 폭으로 |
| `목록` 토글 | 명령바에서 왼쪽 판을 접고 편다. 접기 전 폭을 기억해 되돌린다 |
| 내 프롬프트 | 같은 구분선. 폭은 따로 저장 |
| 1024×700 | 편집기 최소 폭을 360·190으로 낮춰 세 판이 들어간다. 좁으면 `목록`을 접는다 |

편집기 안의 이름·설명·프로젝트 폴더 줄은 오른쪽 판 맨 위로 옮겼다. 왼쪽 목록은 규칙 파일이 아니라 출발점이므로 이름 줄과 나란히 있을 이유가 없다.

### 14차 보강 — 고르면 바로 편집기에

처음엔 목록을 골라도 편집기에 실리지 않고 `새로 열기`를 눌러야 했다. 편집 중인 것이 날아갈까 봐 갈라 놓은 것인데, 내 프롬프트는 이미 고르면 바로 실리고 기본 제공은 저장할 때 사본이 된다.
같은 문법이어야 하므로 규칙도 **고르면 편집기에 실리게** 바꾸고 `새로 열기`와 미리보기 탭을 없앴다. 남은 버튼은 `지금 규칙에 추가` 하나다.
목록을 다시 채울 때(라이브러리 저장 뒤) 같은 항목을 되찾는 선택은 편집기를 건드리지 않는다.

## 15차 — 편집 중인 것을 잃지 않게

고르면 바로 실리게 바꾸자 반대편 문제가 생겼다. 편집 중에 다른 항목을 누르면 말없이 날아간다. 두 화면에 같은 보호를 넣었다.

| 상황 | 동작 |
|---|---|
| 깨끗한 상태에서 다른 항목 | 그냥 실린다 |
| 편집 중에 다른 항목 · 새로 만들기 · 열기 · 최근 파일 | `저장하지 않은 변경이 있습니다 / 지금 편집 중인 내용을 버리고 넘어갈까요? 남기려면 취소하고 먼저 저장하세요.` [버리고 넘어가기] [취소]. 기본 버튼은 취소 |
| 취소 | 목록 선택이 원래 항목으로 돌아가고 편집기는 그대로 |
| 라이브러리에 저장 뒤 목록 재채움 | 같은 항목을 되찾는 것이라 묻지 않는다 |

더티 판정은 마지막 열기·저장·새로 만들기 시점의 직렬화 결과와 비교한다. 빈 자리표시자 줄은 직렬화에서 빠지므로 새 문서에 아무것도 안 쓴 상태는 깨끗하다.
앱에서 확인: Rust(깨끗) → 안 묻음, 이름 수정 → Git 고르기 → 대화상자 → 취소 → 선택 Rust·수정한 이름 유지 → 다시 Git → 버리기 → Git 실림 → 새로 만들기(깨끗) → 안 묻음. 내 프롬프트도 같은 순서로.

처음엔 내 프롬프트가 켜질 때부터 더티로 계산돼 첫 항목이 실리지 않았다. 뷰모델 생성 직후 깨끗한 기준을 잡게 고쳤다.

## 16차 — 세션을 열 때 굳던 것

사용자 보고: 세션을 열면 렉이 심하다. 원인은 세 겹이었다.

| 원인 | 고침 |
|---|---|
| 타임라인이 `ScrollViewer` 안 `ItemsControl`이라 최대 500개 메시지 요소를 한 번에 전부 만들고 줄바꿈을 계산했다. 메시지 하나가 수십 KB | `ItemsRepeater`로 바꿔 보이는 것만 그린다. 상한은 2,000으로 올렸다 |
| 파일을 읽으며 메시지마다 UI 스레드로 넘어와 `Add`했다 | `Task.Run` 안에서 한 번에 읽어 메모리에 두고, 완성된 목록을 한 번만 바인딩 |
| `도구 호출 보기` 토글이 파일을 다시 읽었다 | 메모리에서 다시 건다 |
| 긴 본문(도구 출력·긴 답변)이 통째로 그려졌다 | 1,500자에서 접고 `더 보기 (N자 더)` / `접기` |
| 로딩 중 다른 세션을 고르면 두 읽기가 겹쳤다 | 앞의 읽기를 취소 |

재기: 25.0 MB(사용자 41·어시스턴트 231) 세션 선택 → **0.5초**에 채워짐, 그동안 UI 최대 응답 지연 9ms, 실제로 그려진 메시지 요소 10개, 도구 호출 토글 뒤 응답 5ms. 94.6 MB Codex 세션도 UI가 굳지 않았다.

같은 회차에 잡은 것 둘: 본문 위에 떠다니던 `Ctrl+1` 풍선(셸 격자 가속기 표시 모드를 숨김으로), 그리고 12차에 "죽은 키"로 지운 17개 중 16개가 실제로는 `switch` 식 안에서 쓰이고 있어 `Role_User`·`Sessions_ListHeader`·`Common_All`이 화면에 키 이름 그대로 노출됐던 것. 이력에서 복구했고, 점검 기준을 "따옴표 안 리터럴 전부"로 넓혔다.

## 17차 — 세 번째 도구

Gemini CLI를 넣고 도구가 셋이 됐다. 요약의 도구 카드는 1400에서 한 줄에 셋, 1024에서 둘+하나로 줄을 바꾼다. 터미널에 `Gemini 프리셋`과 `Gemini 열기`가 같은 자리 규칙으로 붙었다.
Gemini 카드가 계정 라벨과 이메일 줄에 같은 주소를 두 번 보여 라벨을 `Google`로 바꿨다. "두 도구"라고 박아 둔 문구 둘(요약 부제, 정보 카드 상표 문구)을 도구 수에 매이지 않게 고쳤다.

## 18차 — 설치 안 된 도구는 버튼이 설치

Gemini를 넣고 보니 터미널의 `Gemini 열기`는 설치가 안 된 PC에서 눌러도 셸이 명령을 못 찾고 끝난다. 버튼이 상황을 알아야 한다.

| 상태 | 버튼 | 아래 한 줄 | 미리보기 |
|---|---|---|---|
| 설치됨 | `{도구} 열기` (터미널 아이콘) | 없음 | `Gemini ▸ gemini --resume …` |
| 미설치 | `{도구} 설치` (내려받기 아이콘). 폴더가 없어도 눌린다 | `설치되지 않았습니다. 누르면 새 터미널에서 실행합니다: npm install -g …` | `Gemini ▸ npm install -g @google/gemini-cli` |
| 설치 도는 중 | `{도구} 설치 중…` 잠김 | 같음 | 같음 |
| 설치 확인 | 저절로 `열기`로 | 사라짐 | 열기 명령으로 |

버튼·프리셋·미리보기 셋을 도구별 줄 하나(`ToolLaunchViewModel`)로 바꿔 세 도구가 같은 틀을 쓴다. 도구가 더 늘어도 화면은 그대로다.

## 19차 — 코드 점검: 당황하지 않기 위한 안전망

시나리오를 쓰며 당황한 일 셋을 되짚어 원인을 코드로 막았다.

| 당황한 일 | 원인 | 막은 방법 |
|---|---|---|
| 새 빌드를 검수했다고 믿었는데 옛 빌드였다 (두 번) | 솔루션 빌드는 `bind\Debug`, 프로젝트 빌드는 `bin\Debug`로 산출물이 갈렸다 | csproj `AppendPlatformToOutputPath=false`로 폴더 하나. `tools/run-app.ps1`은 MSBuild에 출력 폴더를 물어 빌드한 그 파일을 띄운다. CLAUDE.md에 규칙 |
| "죽은 키"라며 지운 문구 16개가 화면에 키 이름 그대로 떴다 | 점검 정규식이 `UiStrings.Get("…")` 꼴만 봤다. switch 식 안 리터럴을 놓쳤다 | `StringResourceKeysTests` — 코드가 부르는 키는 resw에 있고, resw 키는 어딘가 불려야 한다. 따옴표 안 리터럴 전부를 참조로 본다 |
| 세션을 여는 동안 필터를 바꿔도 아무 일이 없었을 것 | 타임라인 읽기가 목록 작업과 같은 `IsBusy`를 켰고, 필터는 `IsBusy`면 무시했다 | 타임라인은 `IsTimelineLoading`만 쓴다 |

덤으로 잡은 것: 세션 파일이 잠기거나 지워진 채 고르면 `async void` 핸들러에서 IOException이 튀어 앱이 죽을 수 있었다. 뷰모델에서 잡아 `세션 파일을 읽지 못했습니다: …`로 보여준다.
전역 `CrashReporter`는 이미 있었다.

## 20차 — 요약·터미널 탭

도구가 셋이 되자 요약 카드 셋과 터미널 버튼 셋이 한 화면에 나란히 놓여 어디를 봐야 할지 흐려졌다. 두 화면에 탭 띠(`SelectorBar`)를 넣었다.

| 화면 | 탭 | 탭이 바꾸는 것 |
|---|---|---|
| 요약 | `전체 · Codex · Claude · Gemini` | 도구 카드(전체면 셋, 도구 탭이면 그 하나), 최근 세션, 세션 수·용량, 최근 7일 토큰(인덱스에 도구로 좁혀 다시 물음) |
| 터미널 | `Codex · Claude · Gemini` | 옵션 인자(탭마다 따로 기억), 프리셋, 열기/설치 버튼, 실행될 명령. 작업 폴더는 공통이라 탭 위에 둠 |

도구 순서를 `ToolLook.DisplayOrder`(Codex → Claude → Gemini) 한 곳으로 모아 요약 탭·카드, 터미널 탭, 세션 필터, 컨텍스트 토글이 같은 순서를 쓴다.

앱에서 확인: 요약 전체 탭 카드 순서 `Codex CLI, Claude Code, Gemini CLI` → Codex 탭 `Codex CLI`만 → Gemini 탭 `Gemini CLI`만. 터미널 Claude 탭에 `--continue`를 넣고 Gemini 탭으로 갔다가 돌아와도 `claude --continue`가 남아 있다.

중간에 잡은 것: 순서 정렬에 컬렉션 식을 `List`로 캐스팅한 코드가 들어가 앱이 켜지자마자 죽었다(`InvalidCastException`). `CrashReporter`가 남긴 로그로 바로 찾았고, 캐스팅 없는 탐색으로 고쳤다.
