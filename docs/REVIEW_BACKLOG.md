# 코드 검토 잔여 건

> [UI_TOKENS_PLAN.md](UI_TOKENS_PLAN.md) 가 끝난 뒤 남은 것들.
> 2026-09-10 전면 검토에서 나온 지적 중 아직 손대지 않은 것을 여기서 0으로 만든다.
> 각 건은 **커밋 하나 + 이 문서 갱신**이다.

## 원칙

- **고친다**: 동작이 틀렸거나, 조용히 실패하거나, 값이 여러 곳에 흩어진 것.
- **보고만 한다**: 화면이 실제로 달라지거나, 앱이 하는 일의 범위가 바뀌는 것.
  이건 버그가 아니라 다음 리팩터링 건이다.
- 앱은 실행하지 않는다. 확인은 빌드 · 테스트 · 기계 검증으로 한다.

## 2차 — 실제 실행에서 나온 버그 + 승인된 리팩터

2026-09-10 앱을 띄워 보고 나온 것과, 앞서 "보고만" 으로 미뤄 뒀다가 승인된 것들.

| # | 건 | 성격 | 상태 |
|---|---|---|---|
| B1 | 제목줄 뒤로 단추만 크기·글리프가 다름 | 화면 | ✅ |
| B2 | 도구 탭을 빨리 바꾸면 목록이 앞 탭에 머묾 | 동작 오류 | ✅ |
| B3 | 저장 실패 같은 알림을 좌측 하단에 빨갛게 모으기 | 화면 | ✅ |
| A1 | 글자 10단계 → 5단계, 간격 `10`·`14` 눈금 스냅 | 디자인 | ⬜ |

| A5 | 마이그레이션을 도구 3개로 확장 | 기능 | ⬜ |

### 원인 (고치기 전에 찾은 것)

- **B1** — 뒤로는 `muxc:TitleBar` 의 **내장** 단추이고, 앞으로·메뉴는 `LeftHeader` 에 직접 그린
  `36x32` 단추(글리프 16)다. 내장 단추의 글리프 크기는 WinUI 가 정하므로 둘이 맞을 수가 없다.
  상자 크기를 맞춰 둔 주석은 있었지만 **글리프는 맞출 방법이 없었다.**
  → 뒤로도 `LeftHeader` 로 내려 셋을 같은 단추로 만든다.
- **B2** — `ReloadForFilter()` 가 `if (!IsBusy)` 로 감싸여 있어, **읽는 중에 바뀐 필터를 통째로 버린다.**
  R4 에서 고친 것과 같은 결함이 한 곳 더 있었던 것이다.
  Codex 를 누른 직후(아직 읽는 중) 전체를 누르면 탭만 전체가 되고 목록은 Codex 인 채로 남는다.
  - *정정:* R4 기록에 "`ApplyFiltersCommand` 는 어디서도 바인딩되지 않는다"고 적었는데 **틀렸다.**
    XAML 에서 안 쓸 뿐 `ReloadForFilter()` 가 쓰고 있었다. 지웠으면 필터가 통째로 멎을 뻔했다.
- **B3** — R3 에서 저장 실패를 설정 화면 안에만 띄웠다. 설정 화면을 안 보고 있으면 못 본다.
  셸 하단 상태바(`StatusBar`)가 이미 있으니 거기로 모은다. 알림 통로를 하나로 만들어 두면
  앞으로 다른 실패도 같은 자리에 붙일 수 있다.

## 작업 기록

- **R1** — `ToolLookTests` 추가. `Title` · `Vendor` · `Short` · `Initial` · `Color` · `LogoPath` 여섯 switch 와
  `DisplayOrder` 가 모든 `ToolKind` 를 다루는지 본다.
  `ToolKind` 에 `Cursor` 를 임시로 더해 보니 **8곳이 정확히 빨개졌다**. 원복 확인.
  - 폴백(`_ =>`)을 지울 수는 없다 — switch 식은 모든 입력을 받아야 한다. 그래서 "빠진 것"을 밖에서 본다.
- **R2** — `App.DisposeServices()` 를 만들고 `ShellWindow.OnClosed` 가 **설정을 쓴 다음에** 부른다.
  싱글턴 중 `IDisposable` 인 것들(특히 `SqliteSessionIndex` 의 쓰기 연결)이 닫히고 WAL 체크포인트가 돈다.
  해제 자체가 실패해도 종료를 막지 않는다.
- **R3** — 처음에 "실패하면 `Changed` 를 쏘지 말자"로 고쳤다가 **되물렀다**.
  메모리의 `Current` 는 이미 바뀐 뒤라, 알림을 막으면 화면이 메모리 값과도 어긋난다.
  진짜 결함은 재계산이 아니라 **실패를 아무도 모른다**는 것이었다.
  `ISettingsStore.LastSaveError` 를 두고, 설정 화면의 파일 위치 아래에 까닭을 붉게 한 줄 띄운다.
  까닭은 `SensitiveTextMasker` 를 거쳐 적는다 (예외 메시지에 경로·토큰이 섞일 수 있다).
- **R4** — 세대 번호로 바꿨다. 여기는 요약·사용량 화면과 사정이 다르다:
  `LoadCommand` 와 삭제 뒤의 `await LoadAsync(default)` 는 **서로를 끊지 않는다**(뒤엣것은 취소 토큰이 없다).
  그래서 세대 번호를 `await` **뒤에도** 확인해, 늦게 온 옛 결과가 화면을 덮지 않게 했다.
  요약·사용량 쪽은 두 실행이 같은 명령이라 앞의 토큰이 끊기므로 이 확인이 따로 필요 없다.
  - *덧:* `ApplyFiltersCommand` 는 XAML·코드 어디서도 바인딩되지 않는다. 남은 껍데기지만 해롭지 않아 두었다.
- **R5** — `ShellNavigationTests` 추가. 넷을 잠근다:
  메뉴 `Tag` 마다 `Navigate` switch 에 자리가 있는가 · switch 가 가리키는 화면 파일이 있는가 ·
  **메뉴에서 갈 수 없는 화면 파일이 있는가**(`PageSkeletonTests` 는 개수만 세고 도달 가능성은 안 본다) · 메뉴가 일곱인가.
  메뉴 항목만 더하고 배선을 빼 보니 **둘이 정확히 빨개졌다**. 원복 확인.
  - XAML 을 글이 아니라 `XDocument` 트리로 읽는다. 속성 순서나 줄바꿈이 바뀌어도 흔들리지 않는다.
- **R6** — **먼저 재고 나서 계획이 틀렸다는 걸 알았다.**
  제가 앞서 "`Card`·`StatTile` 어휘를 만들면 깊이 16 → 4"라고 했는데, 실제로 재 보니 그렇지 않다.
  `SessionsPage` 의 가장 깊은 경로는 이렇다:

  ```
  Page > PageBody > Grid > Border > Pivot > PivotItem > Grid > ScrollViewer
       > StackPanel > ItemsRepeater > DataTemplate > Grid > StackPanel > StackPanel > Border
  ```

  - 앞의 **8겹은 화면 골격**이다. `Card` 같은 컴포넌트로는 한 겹도 안 준다.
  - 뒤의 겹은 **`DataTemplate` 안**이다. 여기를 컴포넌트로 빼면 `{x:Bind}` 컴파일 바인딩을 잃고
    `PropertyChanged` 를 손으로 구독하게 된다 — 터미널·내 규칙 화면의 코드비하인드가 845·770줄이 된 바로 그 길이다.
  - `Card` 가 없앨 수 있는 것은 `Border`+`StackPanel` 두 겹뿐이고, 그마저 깊이가 문제가 아닌 화면들에서만 그렇다.

  그래서 어휘를 짓는 대신 **잰 것에서 나온 것만** 했다:

  1. `SessionsPage` 456줄의 **껍데기 `StackPanel`** 을 없앴다. 자식이 둘인데 둘은 서로 배타적 가시성이라
     같은 격자 칸에 놓으면 된다. 들여쓰기도 어긋나 있던 걸로 보아 편집하다 남은 것이다. 16 → 15겹(새 기준 16).
  2. **깊이 래칫 테스트** `PageDepthTests` 를 켰다. 지금 값을 적어 두고 더 깊어지면 실패한다.
     예산보다 2겹 이상 얕아져도 실패한다 — 줄였으면 표를 내려 래칫을 조이라는 뜻이다.
     새 화면을 예산에 안 적어도 실패한다.
     `UsagePage` 에 `StackPanel` 하나를 덧대 보니 정확히 빨개졌다. 원복 확인.
  - *도중에 잡은 것:* 첫 검사기는 `<TextBlock />` 같은 자기 닫는 잎을 겹으로 안 셌다.
    그러면 같은 트리도 `<X/>` 로 쓰느냐 `<X></X>` 로 쓰느냐에 따라 값이 달라진다.
    형식이 아니라 트리를 재도록 고쳤다(그래서 예산 수가 1씩 올라갔다).
- **B1** — 뒤로를 `LeftHeader` 로 내려 앞으로·메뉴와 같은 `36x32` 단추(글리프 16, `E72B`)로 만들었다.
  `TitleBar.IsBackButtonVisible=False`. 내장 단추가 사라졌으니 `TitleBarBackButtonWidth` 자원과
  가드 테스트의 예외 항목도 같이 지웠다.
- **B2** — `ReloadForFilter` 의 `if (!IsBusy)` 를 걷어냈다. 동시성은 `LoadAsync` 의 세대 번호가 이미 막는다.
  `ResetFilters` 는 다섯 값을 한꺼번에 바꾸므로 읽기를 다섯 번 시작하지 않도록 `_suspendReload` 로 묶고 끝에 한 번만 읽는다.
- **B3** — `ShellViewModel.Report(string?)` 통로 하나를 만들고, 좌측 하단 상태바가 알림을 빨갛게
  (`SystemFillColorCriticalBrush`) 그린다. 알림이 있으면 진행 문구보다 먼저 보인다 — 실패가 더 급하다.
  설정 저장 실패는 `ISettingsStore.Changed` 를 타고 올라오고, 다음 저장이 성공하면 저절로 지워진다.
  R3 에서 설정 화면 안에 넣었던 줄과 `SaveFailed`/`SaveFailureText` 속성은 걷어냈다 — 알림은 한 자리에만 뜬다.
