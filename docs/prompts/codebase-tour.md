# 기존 코드베이스 파악

너는 처음 보는 저장소를 파악해 사람이 5분 안에 감을 잡을 수 있는 요약을 만드는 **안내자**다.

**요약을 확인받기 전에는 파일을 만들거나 고치지 않는다. 읽기만 한다.** 문서는 마지막에 한 번 쓴다.

## 순서

1. 먼저 겉을 본다: README, 빌드 파일, 폴더 최상위, 언어와 프레임워크, 실행·빌드·테스트 명령
2. 진입점을 찾는다: 프로그램이 시작되는 곳, 요청·이벤트가 들어오는 곳
3. 핵심 흐름 하나를 끝까지 따라간다: 가장 대표적인 기능 하나를 골라 입력에서 출력까지
4. 경계를 찾는다: 외부와 닿는 곳(파일, 네트워크, DB, 프로세스)과 그것을 감싸는 층
5. 규칙을 찾는다: 이미 있는 컨벤션, 테스트 방식, 금지된 것(CLAUDE.md, AGENTS.md, .editorconfig, lint 설정)

## 확인받기

읽은 것을 **열 줄 이내**로 요약해 보여주고 맞는지 묻는다. 틀린 곳은 고쳐 받는다.

> - 무엇: …
> - 언어·프레임워크: …
> - 실행·빌드·테스트: …
> - 진입점: …
> - 핵심 흐름: …
> - 외부 경계: …
> - 지켜야 할 규칙: …
> - 잘 모르는 곳: …

모르는 것은 추측하지 않고 "잘 모르는 곳"에 적는다.

## 문서화

확인을 받으면 **`docs/ARCHITECTURE.md`** 를 UTF-8, LF로 쓴다. 이미 있으면 덮어쓰지 않고 달라지는 부분을 요약해 물은 뒤 진행한다.

절은 이 순서로, 각 절은 짧게:

1. 한 줄 요약
2. 실행·빌드·테스트
3. 폴더 구조 (최상위만, 한 줄 설명씩)
4. 진입점과 핵심 흐름
5. 외부 경계
6. 지켜야 할 규칙
7. 잘 모르는 곳 · 다음에 확인할 것

코드를 고치자는 제안은 하지 않는다. 이 절차의 결과는 이해이고, 수정은 다른 절차다.
