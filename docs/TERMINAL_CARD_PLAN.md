### 이 작업이 무엇인가

새 터미널 카드는 지금 **번호 붙은 네 단계를 2단으로 한 번에** 펼쳐 놓는다.
그런데 이 화면에서 사람이 실제로 정하는 것은 **셋(AI · 폴더 · 새로/이어서)** 뿐이고,
나머지(프롬프트·규칙·옵션 인자·프리셋)는 전부 선택 사항인데 같은 무게로 서 있다.

이 계획은 그것을 **아코디언 단계형**으로 바꾼다. 한 번에 한 단계만 펼치고,
끝난 단계는 한 줄로 접히고, 필수 답이 채워지면 다음이 저절로 열린다.

### 대상 사용자 — 이 결정의 근거

| | |
|---|---|
| 사람 | AI CLI를 처음 써 보는 일반인. 터미널·플래그·세션 ID를 모른다 |
| 아는 것 | "폴더", "어제 하던 거", "새로 시작" |
| 모르는 것 | Codex/Claude/Gemini의 차이, `--sandbox`, `--permission-mode`, uuid, resume |
| 두려운 것 | **"이거 누르면 내 파일 뭐 되는 거 아냐?"** |

마지막 줄이 핵심이다. 지금 화면은 정체불명의 플래그 버튼을 앞에 내놓으면서
정작 "무슨 일이 일어나는가"는 버튼 옆 회색 잔글씨로 숨긴다. **신뢰가 거꾸로 설계돼 있다.**

### 일하는 방식

- **Stage 순서대로 한다.** 앞 단계의 완료 기준을 충족하기 전에 다음을 시작하지 않는다
- **단계마다 커밋한다.** 커밋 뒤 `git push origin main`
- **완료 기준은 눈이 아니라 그림으로 확인한다:**


  고치기 전에 `-OutDir artifacts\before`로 한 벌 찍어 두고 나란히 본다.

## 1. 요약 — 결론부터

1. **번호 ①②③④를 지운다.** 위저드 기호인데 위저드가 아니다. 질문형 소제목으로 바꾼다
2. **2단을 버리고 세로 아코디언 4칸으로.** 한 번에 한 단계만 펼친다
3. **필수 3개(AI·폴더·새로/이어서)만 단계로 세운다.** 나머지는 `▸ 자세한 설정` 하나에 접는다

5. **미리보기를 둘로 나눈다.** 사람 말 한 문장(본문 크기) + 실제 명령(고정폭 + 복사 버튼)
6. **세션 목록을 사람이 읽을 수 있게 만든다.** 상대 시간 · 날짜 그룹 · 검색 · 제목 정제

높이가 거의 안 변한다(항상 `접힌 줄 × 3 + 펼친 단계 1개`). 지금의 레이아웃 흔들림이 구조적으로 사라진다.

## 3. 지켜야 할 제약 (코드에서 나온 것)

### 3.1 외부에서 단계를 건너뛰고 들어온다 — **가장 중요**

`TerminalViewModel.PrepareResume(tool, workingDir, resumeArguments, autoOpen)`.
세션 화면·요약 화면의 "이어서 열기"가 **도구·폴더·세션을 한 번에 심고** 이 화면으로 넘어온다.
`ConsumeAutoOpen()`이 화면 로드 때 도구를 다시 고르고 방을 연다.

→ 단계형은 **1~3단계가 이미 채워진 상태로 도착하는 경로**를 반드시 지원해야 한다.
그때는 세 줄이 접힌 채로 즉시 나타나고, 애니메이션으로 훑지 않는다.
`autoOpen: true`면 지금처럼 곧장 방을 연다(카드를 보여 주지도 않는다).

### 3.2 폴더는 도구 공통, 옵션 인자는 도구별

`WorkingDirectory`는 뷰모델 하나, `Arguments`·`Presets`는 `ToolLaunchViewModel`마다다.
→ AI를 바꿔도 폴더는 유지된다. 옵션 인자는 도구를 따라 바뀐다. **이 동작을 유지한다.**

### 3.3 미설치 도구도 화면을 통과한다

`SelectedTool.IsInstalled` / `EmbeddedButtonText` / `Hint` / `CanPress`가 이미
"설치하기"·"설치 중…"·3초 폴링·5분 타임아웃을 처리한다.
→ 설치가 안 됐다고 단계를 막지 않는다. 폴더도 세션도 고르게 두고,
**실행 줄의 기본 버튼만** `{도구} 설치하기`가 된다(현행 로직 그대로).

### 3.4 다음 단계로 넘어가는 관문은 이미 있다

`CanLaunch => !string.IsNullOrWhiteSpace(WorkingDirectory) && Directory.Exists(WorkingDirectory)`.
→ 2단계의 완료 판정에 그대로 쓴다. 새 조건을 만들지 않는다.

### 3.5 골격은 건드리지 않는다

`PageBody Layout="Wide"`, 탭 띠·방 도구 줄은 `Filters`, 카드는 `Body`.
`PageSkeletonTests`가 MUST 넷을 검사한다 — 특히 **`ColumnDefinition MinWidth` 합 + 210 + `PagePadding` ≤ 1024**.
→ 아코디언은 세로 1단이라 이 검사를 자연히 통과한다. **2단으로 되돌리지 않는다.**

## 4. 목표 골격

### 4.1 규칙

| | |
|---|---|
| **한 번에 한 단계만 펼친다** | 끝난 단계는 한 줄(약 44px)로 접히고 `✓ + 요약 + 변경`만 남는다 |
| **필수 답을 채우면 다음이 열린다** | "다음" 버튼을 따로 두지 않는다. 고르는 순간 현재가 접히고 다음이 펼쳐진다 |
| **목적지는 처음부터 보인다** | 실행 줄은 1단계부터 자리에 있다. 회색이고, 남은 것을 문장으로 알려 준다 |
| **아직 안 온 단계는 흐리게 보인다** | 숨기지 않는다. 몇 개 남았는지 알아야 안심한다 |
| **되돌려도 뒤를 지우지 않는다** | 단, 도구·폴더를 바꾸면 세션 선택만 무효화하고 **왜 무효인지 문장으로 말한다** |

### 4.2 단계 배치

| 단계 | 질문 | 답 | 완료 판정 | 접혔을 때 요약 |
|---|---|---|---|---|
| 1 | 어떤 AI로 시작할까요? | 카드 3장 (로고·이름·제작사·설치 상태) | 고르는 즉시 | `Claude` (미설치면 `Claude · 설치 필요`) |
| 2 | 어느 폴더에서 일할까요? | 콤보 1개 + `찾아보기` | `CanLaunch` | `d-AI-so · 규칙 있음` |
| 3 | 무엇부터 할까요? | 카드 2장 → (새로 시작: 프롬프트 / 이어서: 세션 목록) | 새로 시작 = 즉시 / 이어서 = `SelectedResume != null` | `새로 시작` 또는 `어제 15:02 대화 이어서` |
| — | (실행 줄) | 사람 말 + 명령 + `▸ 자세한 설정` + 버튼 2개 | — | 항상 보임 |

**규칙 상태는 2단계에 붙는다** — 폴더의 속성이지 "시작할 때"의 속성이 아니다.

### 4.9 되돌리기 규칙 — 단계형의 함정

| 3 모드 변경 | 앞 단계 그대로 |
| 자세한 설정 | 아무것도 안 건드림. 도구별 기억 유지 (§3.2) |

**무효화할 때는 반드시 문장으로 알린다.** 조용히 지우면 "내가 고른 게 왜 없어졌지"가 된다.

| 규칙 상태 | 회색 본문 | ✓/— 아이콘 + 색 + `규칙 보기 →`. 2단계 요약줄에도 |

| 세션 시각 | `MM-dd HH:mm` | 24시간 안 → 상대 시간(`3시간 전`), 넘으면 `어제 15:02` / `09-07 13:50` + 날짜 그룹 헤더 |
| 세션 건수 | `나 21 · 답 69` | `주고받음 90회` (툴팁에 `내 질문 21 · 답 69`) |

| 목록 끝 | 반쪽 행으로 잘림 | 행 높이 정수배 `MaxHeight` + `▾ N개 더 보기` |
| 목록 위 | 없음 | 검색칸 + `이 폴더의 대화 N개` |
| 프리셋 | 날 플래그 버튼 | `자세한 설정` 안, 한국어 라벨 앞 · 플래그 뒤 회색. **`--resume`/`--continue` 계열은 삭제** (3단계와 중복) |
| 인자 안내문 | `예: --continue` | `잘 모르면 비워 두세요` |
| 미리보기 | 버튼 옆 회색 잔글씨, 잘림 | 전용 2단 — `PreviewSentence`(사람 말·본문) + `Preview`(명령·고정폭) + 복사 버튼 |

| # | 타입 | 내용 |
|---|---|---|
| 0-1 | `chore` | `Daiso.Core/Sessions/SessionTitle.cs`에 `CleanPrompt`를 **한 글자도 안 바꾸고 이식**하고, `SessionTitleTests`가 **지금 동작**을 고정한다. 아래 결함 둘도 "지금은 이렇게 된다"로 그대로 박는다. **App은 아직 안 건드린다** |

| 0-3 | `fix` | 결함 둘 수정 + 터미널이 이걸 쓰게 한다. 0-1에서 결함을 박아 둔 케이스의 기댓값을 뒤집는다 — **그 diff가 곧 "무엇이 달라지는가"의 전문이다** |

> 안전 성질(바꾸기 전에 고정한다)은 그대로다 — 0-1은 이식이 충실한지를, 0-2는 App이 그 이식본을 쓰는지를 각각 증명한다.
> 이식이 충실했다는 근거: 코드만 읽고 예측한 기댓값 12건이 첫 실행에서 전부 통과했다.

**0-3에서 고치는 결함** (조사에서 나왔다. 세션 화면에도 있다):

| 결함 | 근거 |
|---|---|
| 제어문자·ANSI를 안 지운다 | `char.IsWhiteSpace`는 ESC(`U+001B`)를 안 잡는다. 화면에 네모(□)로 나오는 줄이 이것이다 |

### Stage 1 — 아코디언 골격

- `StepState`(`Done` / `Current` / `Pending`) + `CurrentStep`(0~2) 도입

- 무효화 사유 문자열 속성 추가

**완료 기준**: 1024/1280/1600 캡처에서 상태 0·1·2·3a·3b 다섯 장을 찍어
**카드 높이 변화가 세션 목록이 열릴 때 말고는 60px 이내**. `PageSkeletonTests` 초록.
세션 화면에서 "이어서 열기"로 들어오면 세 줄이 접힌 채 즉시 뜬다.

### Stage 2 — 1단계: AI 카드 3장

- `SelectorBar` → 카드 3장. `ToolLook`에서 이름·제작사·로고. **XAML의 글자 하드코딩 제거**
- 설치 상태 뱃지(`✓ 준비됨` / `설치 안 됨`)
- 기본 선택을 `ToolLook.DisplayOrder` 첫 번째로 (지금 Codex 하드코딩)

**완료 기준**: 도구를 늘려도 XAML을 안 고친다. 미설치 도구를 골라도 2단계로 넘어간다.

### Stage 3 — 2단계: 폴더

- `아는 프로젝트` 드롭다운을 폴더 콤보 안 그룹으로 병합, 남는 자리에 `찾아보기`
- 규칙 상태를 아이콘 + 색 + `규칙 보기 →` 링크로. 요약줄에 `d-AI-so · 규칙 있음`
- 없는 경로면 그 자리에서 `그런 폴더가 없어요`

**완료 기준**: 드롭다운이 하나다. 폴더를 바꾸면 규칙 상태와 3단계 대화 수가 같이 바뀐다.

### Stage 4 — 3단계: 세션

- 라디오 → 카드 2장. `이 폴더 대화 N개` 부연. 0개면 비활성
- 목록에 검색칸 + 날짜 그룹 헤더 + `▾ N개 더 보기`
- 선택 강조를 배경 채움으로. `MaxHeight`를 행 높이 정수배로
- 프롬프트 선택칸을 "새로 시작" 안으로 이동. 안내문을 칸 바로 아래 고정

**완료 기준**: 세션 249건 환경에서 검색어 입력 → 결과까지 1회 클릭.
1024 캡처에서 반쪽 행이 없다.

### Stage 5 — 실행 줄

- `PreviewSentence`(사람 말) 신설. `Preview`에서 `{Label} ▸ ` 접두어 제거 — 복사할 때 방해된다
- 복사 버튼. `TextTrimming` 유지하되 툴팁 + 복사로 전문 접근
- 버튼 글자를 모드에 따라 (`시작하기` / `이어서 열기` / `{도구} 설치하기`)
- 미완료 단계가 있으면 회색 + 남은 것 문장
- 실행 줄을 카드 바닥에 고정해 스크롤해도 보이게 한다 (§7.5)

**완료 기준**: 다섯 상태 각각에서 문장이 실제 실행과 일치한다.
복사 → 붙여넣기 하면 **그대로 실행되는 명령**이다. 1024×768에서 실행 버튼이 보인다.

### Stage 6 — 자세한 설정

- 옵션 인자 + 프리셋을 `Expander` 하나로. 도구별로 펼침 상태 기억
- 프리셋을 한국어 라벨 + 회색 플래그로. `--resume`/`--continue` 계열 삭제
- 탭 띠 `＋ 새 터미널`을 아이콘만으로

**완료 기준**: 기본 화면에 영어 플래그가 하나도 안 보인다. `--resume`이 두 군데 있지 않다.

### Stage 7 — 잠그기 + 문서

- `StringResourceKeysTests` 초록 (문구 키 추가/삭제 반영)
- 새 터미널 카드 구조 테스트: **날 플래그 문자열이 XAML의 기본 표시 경로에 없을 것**
- `docs/ARCHITECTURE.md` §5.3 새 터미널 카드 절을 다시 쓴다
- `docs/UX_SCENARIOS.md`에 §2 문제 20건의 해결 여부를 표로 추가
- 이 문서 §0 "지금 어디까지 됐나"를 채운다

**완료 기준**: `dotnet test` 전체 통과. 1024·1280·1600 × 다섯 상태 캡처가 `artifacts\screens`에 있다.

## 7. 결정 기록

### 7.1 단계 진행 → **답을 채우면 자동으로 다음** (버린 안: "다음" 버튼)

"다음" 버튼을 두면 클릭이 3회 늘고, 일반인이 "골랐는데 왜 안 넘어가지"로 멈춘다.
필수 답이 하나뿐인 단계라 고르는 것 자체가 곧 확정이다.
**예외 없음**: 3단계 "이어서"도 목록에서 고르는 행위가 확정이므로 같은 규칙으로 처리된다.

### 7.2 완료한 단계 → **접되 지우지 않는다** (버린 안: 앞 단계 숨기기)

접힌 줄에 `✓ + 요약 + 변경`을 남긴다. 일반인이 "내가 뭘 골랐더라"를 확인할 곳이 필요하다.
숨기면 되돌아갈 길이 없어 보인다.

### 7.3 전환 → **애니메이션 없음** (버린 안: 접힘/펼침 애니메이션)

이 카드는 `PrepareResume`로 **이미 완성된 상태로 도착하는 경로**가 있다(§3.1).
애니메이션을 넣으면 그 경로에서 세 단계를 훑는 연출이 나와 오히려 느려 보인다.
즉시 전환하고, 대신 새로 열린 단계로 스크롤만 부드럽게 이동한다.

### 7.4 도구 선택 → **탭에서 카드로** (버린 안: SelectorBar 유지)

`ARCHITECTURE.md` §5.3은 도구를 탭으로 두고 옵션 인자를 탭별로 기억한다.
카드로 바꿔도 그 기억은 유지된다(§3.2). 잃는 것은 "각 도구는 별개 화면"이라는 신호인데,
폴더와 세션은 어차피 도구 공통이므로 그 신호는 애초에 사실이 아니었다.
얻는 것은 제작사·설치 상태를 붙일 자리다. 일반인에게는 이쪽이 이득이다.

### 7.5 세로 1단 → **카드가 길어지는 것을 감수** (버린 안: 2단 유지)

900px 창에서 "이어서" 모드는 스크롤이 생긴다.
대신 **실행 줄을 카드 바닥에 고정**해서, 스크롤해도 "무엇이 실행되는가"와 시작 버튼은 항상 보이게 한다.
2단을 유지하면 §2-C의 빈 공간·baseline 문제가 그대로 남고, `PageSkeletonTests`의
`MinWidth` 합 제약도 계속 아슬아슬하다.

### 7.6 `자세한 설정` 접기 → **접는다** (버린 안: 펼친 채 유지)

지금 쓰던 사람은 클릭이 1회 는다. 도구별로 마지막 펼침 상태를 기억해 상쇄한다.
일반인에게 정체불명의 플래그를 첫 화면에 보여 주는 비용이 더 크다.

### 7.7 프롬프트 정제기 → **Core로 올려 공용화** (버린 안: 터미널만 고치기)

`SessionInfo.FirstPrompt` 소비처를 전부 훑은 결과다.

| 사실 | 근거 |
|---|---|
| 정제기가 **이미 있다** | `SessionsViewModel.cs` `CleanPrompt` — `<…>`를 깊이 세기로 걷어내고 공백을 합친다. 세션 목록 제목(`TitleText`)과 세션 상세(`CleanCommandText`)가 쓴다 |
| **터미널만 안 쓴다** | `TerminalViewModel.cs`는 `ReplaceLineEndings(" ").Trim()`뿐. **이미 두 벌이고, 터미널만 고치면 세 벌이 된다** |
| **테스트가 없다** | `tests/` 전체에 `CleanPrompt`·`TitleText` 참조 0건. App 레이어의 `private static`이라 붙일 자리가 없다 |
| **결함 둘이 세션 화면에도 있다** | 제어문자 미제거 · 본문 `<`가 뒤를 삼킴 (Stage 0 표) |

그래서 "터미널만 고치기"는 **같은 버그를 세션 화면에 남기고 로직을 3벌로 늘리는** 선택이라 버렸다.

**자리**: `Daiso.Core/Sessions/SessionTitle.cs`. Core 폴더는 이미 `Rules`·`Instructions`·`Prompts`·`Context`처럼
**영역별 순수 로직**이다. `Sessions`만 순수 로직이 없었던 건 그게 전부 App 레이어에 흘러 있었기 때문이다.
테스트는 `tests/Daiso.Core.Tests/Sessions/SessionTitleTests.cs`.

**위험 대응**: "공용화했다가 세션 화면 표시가 바뀐다"는 §8의 위험은 **커밋 순서로 없앤다**.
지금 동작을 특성화 테스트로 먼저 고정(0-1) → 동작 그대로 이동(0-2) → 그 다음 결함 수정(0-3).
0-3의 기댓값 diff가 곧 "무엇이 달라지는가"의 전문이고, 0-3만 되돌리면 표시가 원래대로 돌아간다.

## 8. 위험과 되돌리기

| 위험 | 대응 |
|---|---|
| `PrepareResume` 경로가 단계형에서 깨진다 | Stage 1의 완료 기준에 명시. 세션 화면 → 이어서 열기를 매 단계 확인 |
| `FirstPrompt` 정제기를 공용화했다가 세션 화면 표시가 바뀐다 | **해소됨** — 조사 완료(§7.7). 커밋 순서로 없앤다: 특성화 테스트 고정(0-1) → 동작 그대로 이동(0-2) → 결함 수정(0-3). 0-3만 되돌리면 원래대로 |
| 아코디언이 자동으로 접히며 사용자가 내용을 잃었다고 느낀다 | 접힌 줄에 요약 + `변경`을 반드시 남긴다(§7.2). 무효화 시 문장 고지(§4.9) |
| 프리셋에서 `--resume` 삭제가 기존 습관을 깬다 | 3단계가 같은 일을 한다. Stage 6 커밋을 독립으로 두어 그 커밋만 되돌릴 수 있게 |
| 세로가 길어져 1024×768에서 실행 버튼이 안 보인다 | 실행 줄 카드 바닥 고정(§7.5). Stage 5 완료 기준에 1024 캡처 포함 |

**되돌리기**: 단계마다 커밋한다. Stage 2·3·4·6은 서로 독립이라 개별 되돌리기가 가능하다.
Stage 1(골격)만 되돌리면 그 위 단계가 다 무너지므로, Stage 1은 완료 기준을 충족하기 전에 다음으로 넘어가지 않는다.
