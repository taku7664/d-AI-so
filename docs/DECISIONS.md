# 결정 기록

왜 WinUI를 버리고 Electron으로 가는지, 그 과정에서 무엇을 정했고 무엇을 버렸는지 적는다.
여기 적힌 결정은 다시 논의하지 않는다. 바꾸려면 이 문서에 이유를 적고 바꾼다.

## 왜 바꾸나

| 이유 | 내용 |
|---|---|
| 화면 품질 | WinUI 레이아웃이 마음에 들지 않는다. HTML/CSS는 AI가 다루기 쉽고 디자인을 빨리 바꿀 수 있다 |
| AI가 화면을 직접 조작 | 같은 화면을 크롬 탭에서 열 수 있으면 AI가 브라우저 도구로 눌러 보고 확인할 수 있다 |
| 생태계 | 컴포넌트·차트·터미널(xterm.js) 같은 화면 라이브러리가 JS 쪽에 훨씬 많다 |
| 성능 요구 | 높지 않다. Chromium 무게를 감수할 만하다 |

## 버그가 난 자리

2026-10-03에 `git log`로 셌다. 커밋 284개 중 `fix`가 98개다. fix 커밋이 건드린 파일은 다음과 같다.

| 프로젝트 | 파일 수 |
|---|---|
| `Daiso.App` (WinUI) | 271 |
| Infrastructure | 22 |
| Core | 20 |
| Providers 6개 합계 | 34 |

버그 대부분이 WinUI 화면과 창 관리에서 났다. 그래서 백엔드는 C#으로 남기고 화면만 바꾼다.

## 정한 것

| 결정 | 이유 | 버린 안 |
|---|---|---|
| **Electron이 기본 앱** | 사람은 앱으로 쓴다. 크롬 탭은 AI에게 시킬 때만 쓴다 | 브라우저 전용 · WebView2 셸 |
| **백엔드는 C# 그대로** | 위 버그 통계. 다 고쳐 둔 파서·인덱스·테스트를 버리지 않는다 | 백엔드까지 TypeScript로 다시 쓰기 (C#에서 막히면 그때 다시 본다) |
| **화면 ↔ 서버는 HTTP + WebSocket** | 크롬 탭에서도 똑같이 돌아야 한다. Electron IPC를 쓰면 크롬 탭에서 안 된다 | Electron IPC · stdio 통신 |
| **Electron 전용 기능은 좁은 다리 하나로** | `window.daisoDesktop`(preload)이 있을 때만 켠다. 없으면(크롬) 기능을 줄여 보여 준다 | 화면 곳곳에서 Electron API 직접 호출 |
| **옛 앱은 `old/`에 두고 새 구조는 루트에 새로 짓는다** | 한 창에 XAML과 웹 화면을 섞을 수 없다. 새 앱이 다 따라잡으면 Stage 8에서 바꾼다 | 화면을 하나씩 옮기며 섞어 쓰기 |
| **백엔드는 복사하지 않고 `old/src`를 참조한다** | 두 벌이 되면 버그를 두 번 고친다. Stage 8에서 `backend/src/`로 옮긴다 | 처음부터 `backend/src/`로 복사 |
| 화면 스택: **Vite + React + TypeScript** | 자료와 예제가 가장 많고 AI가 가장 잘 다룬다 | 바꾸려면 Stage 3 전에 |
| 서버 ↔ 웹 타입: **OpenAPI에서 TS 타입 생성** | C# record와 TS 타입이 어긋나면 런타임에야 터진다. 손으로 두 벌 적지 않는다 | 손으로 맞추기 |
| **최상위를 언어로 나눈다:** `frontend/`(TS) · `backend/`(C#) | 한 폴더에 두 언어와 두 빌드 도구가 섞이지 않는다. 탭은 양쪽에 각자 `tabs` 폴더를 둔다 | 탭 폴더 하나에 화면(TS)과 엔드포인트(C#)를 같이 두기 |
| C# 프로세스 이름: **`Daiso.Host`** | 백엔드 라이브러리와 탭 엔드포인트를 싣고 띄우는 프로세스다. 원격 서버가 아니다 | `Daiso.Server` (원격 서버로 오해) · `Daiso.Backend` (`backend/` 와 겹침) |
| 패키지 매니저: **npm 하나** | Node 24에 같이 깔려 있다. lock 파일은 `package-lock.json` 하나다 | pnpm · yarn |
| 자료 폴더: **옛 앱과 같은 `%LOCALAPPDATA%\DAIso`** (2026-10-05) | 같은 `index.db`로 숫자를 나란히 비교할 수 있고, 다 옮긴 뒤 옛 앱을 지워도 사용자가 옮길 것이 없다. 동시에 띄우는 것은 막지 않는다. 다만 옛 앱은 `settings.json`을 시작할 때 한 번 읽고 저장할 때 통째로 덮어쓰므로(`old/src/Daiso.App/Services/SettingsStore.cs`) **설정은 한쪽에서만 바꾼다** | 새 앱만 다른 폴더 쓰기 · 동시에 띄우면 새 앱은 읽기만 |
| `Daiso.Host` TFM: **`net10.0-windows`** (2026-10-05) | LTS이고 OpenAPI 문서 생성이 내장돼 있다. `-windows`여야 `Infrastructure`(`net8.0-windows`, ConPTY)를 참조할 수 있다 | `net8.0-windows` (OpenAPI에 Swashbuckle 같은 패키지가 따로 필요) |
| TypeScript **5.9** | typescript-eslint 8.71이 6.1 미만만 지원한다 (2026-10-03 확인) | TypeScript 7 |
| 화면 시안: **D안** ([design/README.md](design/README.md)) (2026-10-06) | A·B·C안을 거쳐 정했다. C안은 옛 앱과 배치가 거의 같아서, 기능을 만든 사람의 분류가 아니라 사용자가 하는 일 순서로 다시 짰다 | 옛 배치 그대로 · VSCode식 도킹 · 탭 없이 한 화면 |
| **"지금 프로젝트"가 앱 전체의 기준** (2026-10-06) | 위 줄에서 프로젝트를 한 번 고르면 요약·터미널·세션·지침·프롬프트·사용량이 모두 그 기준으로 바뀐다. 옛 앱은 탭마다 폴더를 따로 골라서 한 프로젝트 일을 하는 동안 같은 폴더를 세 번 골랐다 | 탭마다 폴더 고르기 |
| **탭은 여섯 개. 설정은 탭이 아니다** (2026-10-06) | 요약·터미널·세션·지침·프롬프트·사용량. 설정은 몇 주에 한 번 여는 화면이라 위 줄의 톱니로 연다. 계정은 위 줄 계정 단추, 돌고 있는 터미널은 위 줄 종에서 본다 | 설정을 일곱째 탭으로 · 탭을 없애고 합치기 (열자마자 무엇이 어디 있는지 모른다) · 가운데 위에 뜨는 명령 팔레트 |
| **요약은 고른 프로젝트의 첫 화면** (2026-10-06) | 열린 터미널, 최근 세션, 손볼 것(지침 못 읽음, 로그인 만료, 정리할 세션)을 보여 준다. "모든 프로젝트"면 프로젝트 카드 목록이다. 계정 카드는 위 줄 계정 단추로 옮겼다 | 계정 카드를 가운데 두는 요약 |
| **사용량은 토큰과 구독 한도만. 단가표와 $ 추정은 없앤다** (2026-10-06) | 구독으로 쓰면 $ 추정은 실제로 내는 돈이 아니다. 구독 한도가 실제로 궁금한 값이다 | 단가표로 $ 추정 |
| **구독 한도는 도구가 남긴 파일로만 읽는다** (2026-10-06) | Codex는 세션 기록(`~/.codex/sessions/…jsonl`)의 `rate_limits`. Claude는 공식 상태줄 입력의 `rate_limits`(`five_hour`·`seven_day`)를 DAIso 상태줄 스크립트가 파일로 남긴다. 상태줄 등록은 사용자 설정 파일(`~/.claude/settings.json`)을 고치므로 화면에서 동의를 받고, 쓰던 상태줄이 있으면 감싼다. 탭을 열 때 비동기로 읽고, 파일이 바뀌면 바로 반영하고, 기준 시각을 붙인다 | 로그인 토큰으로 서버에 직접 묻기 (앱은 토큰을 다루지 않는다) · 탭을 열 때 도구에 짧은 요청 보내기 (한도를 쓰고 쓰레기 세션이 쌓인다) |

| 아이콘: **Bootstrap Icons** (MIT). 글꼴: **Gothic A1 · Hahmlet · JetBrains Mono** (2026-10-06) | D안이 쓰는 그대로. 글꼴은 앱에 동봉한다 | |

## 안 하기로 한 것

- **바깥 플러그인이 탭을 더하는 길.** 계약이 기본 탭으로 굳은 뒤에 따로 계획한다
- **화면 ↔ 서버에 Electron IPC 쓰기.** 크롬 탭에서 안 된다
- **XAML과 웹 화면 섞어 쓰기.** 한 창에서 섞을 수 없다
- **원격 접속.** 서버는 `127.0.0.1`에서만 받는다. 다른 PC에서 여는 기능은 만들지 않는다
- **Context Doctor.** 옛 앱의 지침 진단 화면. 무엇을 하는지 사용자가 알 수 없었다 (2026-10-06)
- **삭제 미리보기와 두 번 확인.** 세션 삭제는 대화상자 하나에서 "휴지통을 거치지 않고 바로 지우기" 체크박스만 묻는다 (2026-10-06)
